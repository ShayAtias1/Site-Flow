# SiteFlow — שלב 0: הוכחת היתכנות (PoC)

זהו **לא** ה-MVP. זו בדיקה של הסיכונים הטכניים לפני שמתחילים לפתח: PWA ב-iPhone, עבודה Offline,
שמירת נתונים, סנכרון ללא דריסה שקטה, ו-PDF בעברית.

## מבנה

| תיקייה | תוכן |
|---|---|
| `src/` | ה-PWA (Vite + React + TypeScript), אחסון מקומי ב-IndexedDB (Dexie) |
| `shared/` | טיפוסים, פרויקט הדגמה, לוגיקת מיזוג תלת-כיוונית |
| `server/` | שרת מקומי: מחליף את הענן (Supabase) לצורך הבדיקה. סנכרון עם גרסאות, תמונות, הפקת PDF |
| `server/report/` | תבניות הדוחות (HTML/CSS) ורינדור ב-Chromium |
| `supabase/migrations/` | אותו חוזה ב-SQL ל-Supabase. **טרם הורץ** |
| `scripts/` | בדיקות אוטומטיות, הפקת דוגמאות PDF, אייקונים |
| `poc-output/` | תוצרי הבדיקות ודוגמאות ה-PDF |

## הרצה במחשב

```bash
npm install
npm run build
npm run server        # http://localhost:8787
```

```bash
npm run pdf:samples   # poc-output/sample-table.pdf + sample-detailed.pdf
npm run test:poc      # בדיקות קבלה ב-Chromium
npx tsx scripts/poc-tests.ts webkit   # אותן בדיקות במנוע של Safari
```

## Supabase (M1)

- הגדרות הלקוח ב-`.env.local` (לא נכנס ל-git; ראו `.env.example`). רק המפתח הציבורי (publishable) — לעולם לא מפתח סודי.
- המיגרציה: `supabase/migrations/20261022090000_m1_schema.sql` — טבלאות, RLS לפי ארגון, אחסון פרטי, `push_findings`.
- בדיקות:

```bash
npx supabase start                          # Supabase מקומי (פורטים 553xx), דורש Docker/Colima
npx tsx scripts/m1-db-tests.ts local        # אבטחה ו-RLS מול המקומי
npx tsx scripts/m1-db-tests.ts hosted       # בדיקות אנונימיות מול הפרויקט המאוחסן
npm run test:poc                            # האפליקציה + התחברות (Chromium)
npm run test:poc:webkit                     # אותו דבר ב-WebKit
```

- משתמש חדש: יוצרים ב-Dashboard ‏(Authentication → Users → Add user), ואז ב-SQL Editor:
  `select public.admin_add_member('email@example.com', 'שם החברה', 'owner');`

## סנכרון (M2)

- הממצאים, התמונות והדוחות נשמרים ב-Supabase. השרת המקומי (`server/`) מגיש את האפליקציה ומפיק דוחות PDF בשם המשתמש המחובר.
- פרויקטים מוקמים מתוך האפליקציה (M3, לשונית "פרויקט"). פרויקט הדגמה אפשר עדיין ליצור ב-SQL Editor:
  `select public.admin_seed_demo_project('שם החברה');`
- מכשיר חדש צריך סנכרון אחד עם חיבור (אחרי כניסה) כדי לקבל את הגדרות הפרויקט; משם אפשר לעבוד בלי קליטה.
- ממצאי בדיקה מגרסת ה-PoC (פרויקט הדגמה הישן) הועברו בעדכון לטבלאות נפרדות במכשיר ואינם מסונכרנים.

## הקמת פרויקט (M3)

לשונית **פרויקט** (בעלים ומהנדסים; צופה רואה בלבד):

- **פרויקטים**: יצירה, עריכה, מעבר בין פרויקטים, ארכיון. הפרויקט הפעיל נשמר לכל מכשיר. קוד הפרויקט ייחודי בארגון (מופיע במספרי הדוחות).
- **מבנה**: מחולל בניין — טווח קומות (כולל קרקע ומרתפים), דירות בקומה, מספור רציף או לפי קומה, שטחים משותפים. הוספת קומות לבניין קיים ממשיכה את המספור. עריכה ידנית: שינוי שם וקוד, סדר, הוספת דירה או שטח, אזורי פיתוח.
- **קבלנים**: לכל פרויקט רשימה משלו, עם מקצוע ופרטי קשר. פרטי הקבלן משותפים לארגון.
- **קטגוריות**: משותפות לארגון, עם ביטויים מוכנים. קבלן ברירת המחדל לכל קטגוריה נקבע לכל פרויקט בנפרד.

כללים שנאכפים גם בשרת (`supabase/migrations/20261022180000_m3_project_setup.sql`): אי אפשר למחוק מיקום שיש בו או מתחתיו ממצאים; מיקום לא עובר בין פרויקטים ולא נתלה תחת מיקום של פרויקט אחר; מחיקה היא תמיד רכה.

עריכת ההגדרות דורשת חיבור. אחרי סנכרון, הפרויקט כולו זמין לתיעוד גם ללא חיבור.

```bash
npm run test:m3            # הקמת פרויקט, הפרדה בין פרויקטים, הגנת מחיקה (Chromium)
npm run test:m3:webkit     # אותו דבר ב-WebKit
```

## סיורים והיסטוריה (M4)

- **תיעוד מתחיל בסיור**: תאריך, סוג (ראשוני / חוזר / אימות-מסירה), משתתפים והערות. אפשר לפתוח סיור גם ללא חיבור. הסיור הפעיל נשמר לכל פרויקט במכשיר; מכשיר אחר יכול להמשיך סיור פתוח.
- **כל ממצא חדש משויך לסיור** שבו תועד. ממצאים מלפני M4 נשארים ללא סיור — לא משויכים בדיעבד.
- **היסטוריה**: כל שינוי (יצירה, סטטוס, שדות, מחיקה, שחזור, פתרון התנגשות) נרשם במכשיר ברגע שקרה — עם הזמן, הסיור והמשתמש — ונשלח יחד עם הממצא. השרת שומר כל אירוע פעם אחת, וגוזר היסטוריה בעצמו עבור גרסה ישנה של האפליקציה.
- **עריכת ממצא**: תיאור, קטגוריה, מיקום, קבלן, סיווג וסטטוס. **מחיקה רכה** עם שחזור (רשימת "נמחקו").
- **קבלנים**: ממצא חדש — או החלפת קבלן — רק לקבלן פעיל בפרויקט (נאכף גם בשרת). ממצא קיים שומר קבלן שהוסר.
- **טיוטה לכל פרויקט**: מעבר בין פרויקטים לא מעביר טקסט או תמונות.

```bash
npm run test:m4            # סיורים, היסטוריה, עריכה ומחיקה, Offline (Chromium)
npm run test:m4:webkit     # אותו דבר ב-WebKit
```

## ממצא בכמה מיקומים ותמונות לממצא קיים (M5)

- **כמה מיקומים**: בבורר המיקומים ← "כמה מיקומים" (המיקום הנוכחי מסומן מראש; "הכול" ליד קומה מסמן את כל היחידות בה; אפשר גם בחיפוש). השמירה יוצרת **ממצא נפרד לכל מיקום** — מזהה, מספר, סטטוס והיסטוריה משלו — עם `batch_id` משותף. קטגוריה, קבלן ברירת מחדל ותמונות שצולמו בתיעוד משותפים לכולם (קובץ התמונה נשמר פעם אחת).
- **תמונות לממצא קיים**: בעריכת ממצא, כפתור המצלמה. התמונות הקיימות לא משתנות; כל תמונה חדשה נרשמת בהיסטוריה ("נוספה תמונה") עם הסיור שבו צולמה, ונשמרת בשרת כסוג `progress`. תמונה אינה חובה.
- דוחות שכבר הונפקו אינם משתנים; דוח חדש כולל את התמונות החדשות.

```bash
npm run test:m5            # קבוצות, Offline, תמונות לממצא קיים, דוח נעול (Chromium)
npm run test:m5:webkit     # אותו דבר ב-WebKit
```

## ניהול ממצאים, דוחות מקצועיים וייצוא ל-Excel (M6–M8)

- **טבלת ניהול** (ממצאים ← "טבלת ניהול"; במסך רחב זו ברירת המחדל):
  - חיפוש בתיאור, מיקום וקוד מיקום, קבלן וקטגוריה. `#123` מחפש מספר ממצא מדויק.
  - סינון לפי פרויקט, בניין, קומה, דירה, קבלן, קטגוריה, סיווג, סטטוס, סיור ומצב (פעילים / נמחקו / הכול).
  - מיון לפי כל עמודה, ועריכה בתוך הטבלה של קבלן, סיווג וסטטוס.
  - בחירה מרובה, גם של כל המסוננים, עם פעולות: סטטוס, שיוך קבלן, קטגוריה, סיווג, מחיקה (עם אישור) ושחזור.
  - לחיצה על תיאור פותחת את פאנל הפרטים, עם תמונות והיסטוריה.
  - מוצגות 200 שורות, וכפתור "הצג עוד" מציג את הבאות.
- **עריכה מרובה ושינויים מקבילים**:
  - כל ממצא בעריכה מרובה מקבל אירועי היסטוריה משלו.
  - הוא נשלח עם הגרסה שעליה התבסס, כמו עריכה רגילה.
  - שדה ששונה בינתיים במכשיר אחר הופך להתנגשות שממתינה להחלטה, ולא נדרס.
  - ממצא שנמצא בהתנגשות מדולג בעריכה מרובה, ומוצגת הודעה על כך.
- **הגדרות דוח** (דוחות ← "הגדרות דוח", לכל הארגון): שם החברה ופרטיה, לוגו, עורך הדוח ותפקידו, רישום מקצועי (לא חובה) וחתימה.
  - שדה ריק לא מוצג בדוח. המערכת לא משלימה שמות, מספרי רישום או חתימות.
  - לוגו וחתימה נשמרים רק כ-PNG או JPEG מוקטנים.
- **אפשרויות הפקה**:
  - **היקף**: כל הפרויקט, או כל מיקום בעץ (בניין, קומה, דירה, אזור), ואפשר לצמצם לקבלן אחד.
  - **סינון**: סטטוסים (ברירת מחדל: הכול חוץ מ"בוטל"), כל הסיורים או סיורים נבחרים, וליקויים קריטיים בלבד.
  - **קיבוץ**: לפי מיקום (בניין וקומה), לפי קבלן, או ללא קיבוץ.
  - **בעמוד השער**: הסיור שתאריכו ומשתתפיו יוצגו, כותרת והערות.
- **שני פורמטים**: דוח טבלאי מרוכז (A4 לרוחב) ופרוטוקול מפורט עם תמונות (A4 לאורך). שניהם מסומנים כפרוטוקול השלמת עבודות, ולא כאישור הנדסי או בטיחותי.
- **ארכיון**:
  - הורדה ושיתוף של כל דוח (שיתוף קובץ כשהדפדפן תומך; אחרת מועתק קישור זמני).
  - "גרסה מעודכנת": אותו מספר והגדרות, `Rev.N+1`, והמקור לא משתנה.
  - יומן הפצה ידני: נמען, קבלן, ערוץ והערה.
- **Excel**: בטבלת הניהול, "ייצוא ל-Excel" מייצא את המסוננים, או רק את הנבחרים אם נבחרו.
  - גיליון מימין לשמאל, עם שורת כותרת קבועה, סינון אוטומטי, מספרים כמספרים ותאריכים כתאריכים.
  - טקסט שמתחיל ב-`=`, `+`, `-` או `@` נשמר כטקסט (קידומת מרכאה), ואין בקובץ תאי נוסחה.
- מיגרציה: `20261024090000_m7_report_settings.sql`. היא מוסיפה רק טבלת `report_settings` עם RLS, ובדיקה שרישום הפצה שייך לדוח של אותו ארגון.

```bash
npm run test:m9            # M6–M9 על 600 ממצאים ותמונות בגודל אמיתי (Chromium)
npm run test:m9:webkit     # אותו דבר ב-WebKit
```

## שיפורי UX לפי הביקורת (UX-01…UX-15)

- **חלוניות** (`src/screens/Dialog.tsx`): רכיב אחד לכל החלונות באפליקציה.
  - נגישות: `role="dialog"`, שם נגיש ו-`aria-modal`.
  - פוקוס: עובר לחלונית בפתיחה, נשאר בתוכה ב-Tab (גם ב-Safari) וחוזר לכפתור שפתח אותה.
  - Escape סוגר רק את החלונית העליונה, ושאר האפליקציה נעשה `inert` כל עוד החלונית פתוחה.
  - טופס עם שינויים שלא נשמרו שואל לפני סגירה.
- **הקשר פרויקט קבוע**: בכל מסך מוצגים הפרויקט הפעיל, הסיור הפעיל ו"החלף פרויקט". לכל פרויקט טיוטת תיעוד משלו.
- **ממצאים** (רשימה וטבלת ניהול):
  - חיפוש ומסננים משותפים לשתי התצוגות, שנשמרים לכל פרויקט עד סגירת האפליקציה.
  - במובייל: כפתור "מסננים (N)", חלונית עם "החל" ו"איפוס", וצ׳יפים להסרת מסנן.
  - כרטיסים שמציגים את הקבלן והסטטוס.
  - בדסקטופ: טבלה עם בורר עמודות, עמודות מזהות קבועות, ופרטי הממצא לצד הטבלה.
  - עריכה בשורה מציגה "שומר…", "נשמר במכשיר ✓", או "לא נשמר" עם "נסה שוב".
  - עריכה מרובה בשני שלבים: בוחרים ערכים, רואים את ההיקף, ולוחצים "החל על N ממצאים".
- **תיעוד**:
  - "כל הקטגוריות" מציג את כולן.
  - הביטויים המהירים מופיעים מתחת לתיאור, וכפתור הצילום ליד התיאור.
  - בבחירה מרובה: מונה, "נקה בחירה" ונתיב מלא. כפתור השמירה אומר "שמור N ממצאים", עם הסבר שתמונות שמצורפות בתיעוד משותפות לכל הממצאים.
  - אחרי שמירה: קישור "לממצאים".
- **סיורים**: בחלונית הסיור הסיכום מופיע ראשון, אחריו פרטי הסיור בעריכה, ואחריהם מה נעשה בסיור. אחרי סגירה מוצעות "הצג את ממצאי הסיור" ו"הכנת דוח לסיור".
- **דוחות**:
  - בחירת סוג הדוח, היקף, סטטוסים וסיורים, וכפתור "הפק דוח" יחיד. קיבוץ, עמוד שער, כותרת והערות מקופלים תחת "אפשרויות נוספות".
  - מוצג סיכום עם הערכה מקומית של מספר הממצאים, בנפרד מהתוצאה שנקבעת בשרת.
  - בארכיון: טביעת SHA-256, גודל הקובץ ו"גרסה מעודכנת" נמצאים תחת "פרטים ופעולות".
  - יומן ההפצה מסומן כרישום ידני שלא שולח דבר.
- **הגדרות** (לשעבר "מערכת"): מצב שמירה וסנכרון במילים פשוטות, חשבון, פרטי החברה והעורך בדוחות, גיבוי ושחזור. אין במסכי המשתמש כלי אבחון או בדיקה.
  - סימולציית כשל השמירה פעילה רק בבנייה של הבדיקות (`VITE_TEST_HOOKS=1`).
  - קוד הגישה לשרת מוזן בכתובת (`?access=…`) ולא בשדה במסך.
- **הפרויקטים שלי** (לשונית "פרויקטים"): נקודת הכניסה לבחירת פרויקט.
  - כרטיס לכל פרויקט, עם מספר הממצאים הפתוחים, המבנה והסיור הפעיל, ועם הכפתורים "פתח" (לתיעוד) ו"ניהול".
  - "+ פרויקט חדש" פותח חלון. אחרי היצירה מוצגים הצעדים הבאים: מבנה, קבלנים וקטגוריות.
  - מכל מסך של פרויקט אפשר לחזור ב"כל הפרויקטים" שבפס הפרויקט.
  - בכניסה ראשונה למכשיר שיש בו כמה פרויקטים, האפליקציה נפתחת במסך הזה.
- **חלונות**: כל חלון באפליקציה ממורכז ומעוגל, גם במובייל. אין חלונות שעולים מלמטה ואין מגירות צד.
  - הכותרת וכפתור הסגירה קבועים, התוכן נגלל, ופס הפעולות צמוד לתחתית החלון.
  - החלון מותאם לגובה המסך הגלוי, גם כשהמקלדת פתוחה.
  - בחירת מיקום מתוך עריכת ממצא נפתחת באותו חלון, עם "חזרה לממצא".
- **תיבות סימון**: רכיב אחד (`Checkbox`) לכל תיבות הסימון.
  - תיבה מעוגלת של 22px עם סימון ממולא, מצב חלקי ל"בחר הכול", ומצבי מיקוד, השבתה ושגיאה.
  - כל השורה לחיצה, בגובה 44px לפחות.
  - כפתורי הבחירה (radio) מעוצבים באותו סגנון.
- **קטגוריות**: קבלני ברירת המחדל לפרויקט מוצגים בנפרד מספריית הקטגוריות והביטויים של הארגון.

```bash
npm run test:ux            # מקלדת וחלוניות, רוחבים 320–1440, מסננים, ניגודיות (Chromium)
npm run test:ux:webkit     # אותו דבר ב-WebKit
```

## בדיקה באייפון

ב-iPhone, PWA דורשת **HTTPS**. אפשר להגיע לשרת המקומי דרך מנהרה זמנית:

```bash
brew install cloudflared
SITEFLOW_TOKEN=<קוד-סודי> npm run server
cloudflared tunnel --url http://localhost:8787
```

המנהרה נותנת כתובת `https://….trycloudflare.com`. היא **ציבורית** כל עוד היא פתוחה, ולכן חובה להגדיר קוד גישה
(`SITEFLOW_TOKEN`). בפעם הראשונה פותחים את האפליקציה בכתובת `https://….trycloudflare.com/?access=<קוד-סודי>`. הקוד נשמר במכשיר ונמחק מיד משורת הכתובת.
